# C2000MAX V37.01：网络正确性补丁与 Wi-Fi SDK / ITB 评估

日期：2026-09-08。源码分支：`37.01`，从已推送的 `v36.5` 提交 `763b31f97c72d20376d1ab4b7650651f4a706e2d` 创建。本文记录本地适配范围，不代表设备已经运行本版本。最终源码 SHA、配置、软件包清单、镜像校验和随产物单独提供。

## 本版实际变化

| 候选 | 原基线的实际状态 | V37.01 处理 |
|---|---|---|
| WHNAT 分配时可能睡眠 | 原始源码与全部补丁展开后的源码都在 `spin_lock_bh` 内用 `kmalloc(..., GFP_KERNEL)` | 改为 `kzalloc(..., GFP_ATOMIC)`，保留失败解锁与返回；只改单点 |
| QDMA 队列编号掩码 | MAX 的后续补丁已扩展为 64 队列，但仍使用 `GENMASK(15,0)` | 改为 `MTK_QDMA_NUM_QUEUES - 1`；MAX 为 0x3f，非该配置为 0x0f，不改变队列数 |
| 非 IP L2_BRIDGE 绑定 | 先解析 IP version，非 IP 帧提前失败 | 先识别已有 L2_BRIDGE 类型、检查 l2br_toggle，再从 EtherType 取协议；不默认开启 L2 加速 |
| 新 Wi-Fi 8.3.1.3 SDK | 新版确实存在，但主驱动、WARP、OSAL 三个包均未取得 | 未升级 SDK；保留实际 8.3.1.2 配套，不修改 EEPROM/SKU/MAC 来源 |
| MAC 读取维护补丁 | 补丁文本可应用，但本地缺新 `mt_mac_address_read_wifi()` 后端 | 延后成套适配，避免单独合入未解决符号和错误的 Factory 路径 |
| HWIFI FW_HDR 可选 | 可用旧 SDK 评估，但上游默认改为从文件加载固件 | 本版保留内嵌来源；未验证冷启动/重载前不改变装载路径 |
| WARP 缩环 | 已有，配置已开启 | 保留，不冒充新增功能 |
| FE misc IRQ / SER 恢复 | 尚未包含；IRQ资源存在但通知/生命周期需要整合 | 延后独立适配，不改变 reset.force 和默认恢复行为 |
| 低阈值提前绑定 | 尚未包含，原默认阈值 30 | 延后，保留 OAF hold/释放/阻断时序和默认阈值 |

前三项分别按 [MediaTek 原子分配修复](https://github.com/mediatek/mtk-openwrt-feeds/commit/f789c4f562568768cbde640b6480088bc59cc632)、[队列编号掩码修复](https://github.com/mediatek/mtk-openwrt-feeds/commit/b0a1258f0fd86ff40f9a4e29ef2ad4950c237f6b)、[非 IP L2_BRIDGE 修复](https://github.com/mediatek/mtk-openwrt-feeds/commit/103eb0e4ef5f749198ad4a82a6ee898b86354e93) 移植。采用追加补丁，不覆盖整个 HNAT、以太网或 Wi-Fi 目录。

本版仍为 AP Driver **8.3.1.2** / Linux **6.12.94**：

- 主驱动、HWIFI、CMN：`mt7993_20250613-415824.tar.xz`。
- WARP：`warp_20250613-433271.tar.xz`，保留 mt7987 / WARP 3_1。
- OSAL：`mt_wifi_osal-543726.tar.xz`。

旧包的实际 SHA-256 均与包定义和作者公开资产一致。已检查 HiGoWRT 的固定及当前源码、Release、作者 objs 资产与 IOPSYS 记录；本次未找到可实际取得的新版完整授权公开包，用户也确认没有 SDK。HiGoWRT 没有随仓库提供这些压缩包，包定义的下载 URL 为空。[HiGoWRT 固定 README](https://github.com/Hiveton/higowrt/blob/25a3aefa7be5821fa7e5e4809ac34a09fa62ef24/README.md)

`V37.01` 是本固件版本，不是 Wi-Fi SDK 版本提升。WHNAT 原子分配修复涉及无线加速连接处理，但未证明它是此前低吞吐或网页卡顿的根因，也不承诺峰值提升。

## 保留的 MAX 定制与默认行为

- HQoS/EQoS、NRQOS3 保留。合法 60/61/62 队列及 USB PPD 63 不被截断；不改变上传/下载限速配置和 `-1` 语义。
- NR QoS 整体默认关闭，设备限速优先、二者互斥；硬件下行仍属实验模式，不是此次新实现。
- 保留 HNAT MIB 统计、OAF 按流 hold/释放/阻断和单流清理，不改回高频全表扫描或全局冲刷。
- 保留外部模组 RXPPD、FDB/flooding 检查、网口切换/mwan3 和既有生命周期保护。
- 保留 OWE 有界复制修复、MLO 默认关闭与互锁、2.4 GHz 信道 6、原高性能模式和 WARP 缩环。
- 保留 TF 首启扩容、官方 SPI 已暴露分区只读、不暴露官方 firmware 分区、官方一次性启动功能禁用。没有增加 SPI/bootenv 写入路径。

原有 DFS 调试配置仍然存在（DfsEnable=0）；只应在合规的测试环境使用，不能将本镜像视为通用区域法规配置。

## FE/SER 为什么本轮不混入

[官方 FE/SER 更新](https://github.com/mediatek/mtk-openwrt-feeds/commit/13c73de25ef3f53f5dabdc2f2b410f3aaccbcd0d) 涉及五个补丁与新增异步 IRQ 入口。MAX 的 IRQ 常量/数组布局、Wi-Fi 完成通知、旧 STOP_TRAFFIC 事件状态和 5119 生命周期保护需要共同设计；文本可应用或编译通过不能证明复位过程中接口、PPE、外部设备和 Wi-Fi 能恢复。本轮保留原行为并提供单独评估，不删除保护或改默认开关以求通过。

## ITB 结论：可设计，现版不能直接升级

当前 `sysupgrade.bin` 是 tar + OpenWrt 元数据，里面的 **kernel 已经是 FIT**；TF 上 kernel/rootfs 是独立分区。v36.5 检查器只接受 tar，通用 FIT 写入器则会把整包写到 kernel 分区。MAX 的 kernel 分区只有 32 MiB，现有 rootfs 本身已约 92 MiB，因此不能只改后缀或放宽检查来接收完整 ITB。

推荐未来方案：先通过普通 BIN 安装双格式接收器，再让 ITB 仅充当升级容器，严格校验并分别写入原有 TF kernel/rootfs。这样在设计上不需要修改 SPI 引导器；仍需校验边界、机型、hash、尺寸、提取/写入错误、配置保留与断电恢复。FIT hash 不等同可信签名，换格式也不会使原地升级自动具有 A/B 原子性。[U-Boot FIT 文档](https://docs.u-boot.org/en/latest/usage/fit/index.html)、[OpenWrt eMMC 升级实现](https://github.com/openwrt/openwrt/blob/main/package/base-files/files/lib/upgrade/emmc.sh)

本版未实现 ITB 接收器，**不交付可刷 ITB**。继续提供 BIN、IMG/IMG.GZ：BIN 仅用于 TF ImmortalWrt 内升级，IMG 用于写 TF 卡；任何一种均不应上传到官方系统升级页面。

另一个核查细节：源码中的 `c2000max_tf_upgrade_tar()` 预尺寸/SHA读回助手未被当前板级入口调用，实际走 `c2000max_tf_do_upgrade → emmc_do_upgrade`。本报告不将未调用助手的保护算作现行能力，也不在此次驱动更新中偷偷切换升级器。TF FIP/env 区域原镜像为空，不能声称 IMG 自带已验证的独立 TF U-Boot。

## 验证边界

本次可验证：完整内核补丁展开；实际源码中的非睡眠分配及失败解锁；提取协议选择代码的宿主测试（全部 EtherType、L2 gate、IPv4/IPv6、PPPoE）；16/64 队列掩码全低16位输入和上下行不同队列/高位标记样例；现有脚本回归；本地编译、最终 rootfs/DTB/包清单及 IMG/BIN payload 一致性与 SHA256。
